CRUD completo, URIs y códigos de estado

Esta guía es autocontenida: no importa si ya hiciste la práctica de la Semana 1 o no. Vas a construir (o reconstruir) una API de Productos en NestJS + TypeScript y completarla con POST, PUT, PATCH y DELETE, verificando cada paso antes de avanzar al siguiente.

2.5 h laboratorio Nivel: principiante NestJS + TypeScript Swagger (y opcionalmente Postman)
Regla de esta guía: sigue los pasos en orden, sin saltarte ninguno. Cada paso tiene una casilla de Verificación — el botón "Marcar paso completado" solo se activa cuando confirmas que la verificación se cumplió. Si te saltas un paso, los siguientes probablemente fallarán.
Nota: en contenido/clase 2/practica 2/ existe un proyecto más profundo en .NET (microservicio de Clientes con SQL Server, EF Core y JWT) como pista extendida opcional para comparar el mismo problema en otro stack. import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );

  const config = new DocumentBuilder()
    .setTitle('API de Productos')
    .setDescription('CRUD de productos — Semana 2, Integracion de Sistemas')
    .setVersion('1.0')
    .build();
  const document = SwaggerModule.createDocument(app, config);
  SwaggerModule.setup('swagger', app, document);

  await app.listen(3000);
}
bootstrap();

Paso 2

Generar el módulo de Productos y el primer GET

Vamos a generar con el CLI de Nest la estructura estándar (módulo, controlador, servicio) en vez de escribirla a mano.

  1. En la terminal, dentro del proyecto, ejecuta:
terminal
$ nest g module productos
$ nest g controller productos --no-spec
$ nest g service productos --no-spec
# crea productos.module.ts, productos.controller.ts y productos.service.ts, ya conectados
  1. Crea src/productos/producto.entity.ts:
src/productos/producto.entity.ts
export class Producto {
  id: number;
  nombre: string;
  precio: number;
}

Por ahora, trata esta clase como "una caja con 3 campos: id, nombre y precio" — más adelante podría venir de una base de datos.

  1. Edita src/productos/productos.service.ts:
src/productos/productos.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import { Producto } from './producto.entity';

@Injectable()
export class ProductosService {
  private productos: Producto[] = [
    { id: 1, nombre: 'Teclado mecánico', precio: 45.9 },
    { id: 2, nombre: 'Mouse inalámbrico', precio: 19.5 },
    { id: 3, nombre: 'Monitor 24"', precio: 129.99 },
  ];

  findAll(): Producto[] {
    return this.productos;
  }

  findOne(id: number): Producto {
    const producto = this.productos.find((p) => p.id === id);
    if (!producto) throw new NotFoundException(`Producto ${id} no existe`);
    return producto;
  }
}
  1. Edita src/productos/productos.controller.ts:
src/productos/productos.controller.ts
import { Controller, Get, Param, ParseIntPipe } from '@nestjs/common';
import { ProductosService } from './productos.service';

@Controller('api/v1/productos')
export class ProductosController {
  constructor(private readonly productosService: ProductosService) {}

  @Get()
  listar() {
    return this.productosService.findAll();
  }

  @Get(':id')
  obtener(@Param('id', ParseIntPipe) id: number) {
    return this.productosService.findOne(id);
  }
}

ParseIntPipe convierte y valida que :id sea un entero antes de que tu código lo use; si alguien pide /productos/abc, Nest responde 400 Bad Request automáticamente.

  1. Guarda todo (npm run start:dev recompila solo). Abre /swagger: debe aparecer el grupo Productos con GET /api/v1/productos y GET /api/v1/productos/{id}.
  2. Prueba GET /api/v1/productos (Try it out → Execute): debe responder 200 con 3 productos.
  3. Prueba GET /api/v1/productos/{id} con id=1 (200) y con id=999 (404, gracias al NotFoundException).
Verificación del Paso 2
  • Swagger muestra el grupo Productos con ambos GET.
  • GET /productos/1 responde 200 y GET /productos/999 responde 404.

Paso 4

Implementar POST (crear) con validación por DTO

En NestJS la validación de entrada se declara con decoradores en una clase DTO (Data Transfer Object), y el ValidationPipe global del Paso 1 la aplica automáticamente — no hace falta escribir un if a mano.

  1. Crea src/productos/dto/crear-producto.dto.ts:
dto/crear-producto.dto.ts
import { IsNotEmpty, IsNumber, IsPositive, IsString } from 'class-validator';

export class CrearProductoDto {
  @IsString()
  @IsNotEmpty()
  nombre: string;

  @IsNumber()
  @IsPositive()
  precio: number;
}
  1. Agrega este método a ProductosService:
productos.service.ts
crear(dto: CrearProductoDto): Producto {
  const nuevoId = Math.max(...this.productos.map((p) => p.id)) + 1;
  const nuevo: Producto = { id: nuevoId, ...dto };
  this.productos.push(nuevo);
  return nuevo;
}
  1. Agrega este método al controlador:
productos.controller.ts
import { Response } from 'express';

@Post()
@HttpCode(HttpStatus.CREATED)
crear(@Body() dto: CrearProductoDto, @Res({ passthrough: true }) res: Response) {
  const nuevo = this.productosService.crear(dto);
  res.setHeader('Location', `/api/v1/productos/${nuevo.id}`);
  return nuevo;
}

@Res({ passthrough: true }) te deja seguir devolviendo el objeto normalmente (Nest arma el JSON) mientras también agregas el header Location exigido por el contrato.

  1. Guarda (recarga sola). En Swagger, prueba POST /api/v1/productos con { "nombre": "Audífonos", "precio": 25.00 }. Debe responder 201 Created con header Location.
  2. Prueba también { "nombre": "", "precio": 25.00 }: debe responder 400 Bad Request — generado por el ValidationPipe, sin que tú escribas ese chequeo.
Verificación del Paso 4
  • POST válido responde 201 con header Location.
  • POST con nombre vacío responde 400.
Marca ambas casillas para continuar.
Paso 5

Implementar PUT (reemplazo) y PATCH (parcial)

  1. Crea src/productos/dto/actualizar-precio.dto.ts:
dto/actualizar-precio.dto.ts
import { IsNumber, IsPositive } from 'class-validator';

export class ActualizarPrecioDto {
  @IsNumber()
  @IsPositive()
  precio: number;
}
  1. Agrega estos dos métodos a ProductosService:
productos.service.ts
reemplazar(id: number, dto: CrearProductoDto): void {
  const index = this.productos.findIndex((p) => p.id === id);
  if (index === -1) throw new NotFoundException(`Producto ${id} no existe`);
  this.productos[index] = { id, ...dto };
}

actualizarPrecio(id: number, dto: ActualizarPrecioDto): Producto {
  const index = this.productos.findIndex((p) => p.id === id);
  if (index === -1) throw new NotFoundException(`Producto ${id} no existe`);
  this.productos[index].precio = dto.precio;
  return this.productos[index];
}
  1. Agrega estos dos métodos al controlador:
productos.controller.ts
@Put(':id')
@HttpCode(HttpStatus.NO_CONTENT)
reemplazar(@Param('id', ParseIntPipe) id: number, @Body() dto: CrearProductoDto) {
  this.productosService.reemplazar(id, dto); // 204: sin cuerpo
}

@Patch(':id')
actualizarPrecio(@Param('id', ParseIntPipe) id: number, @Body() dto: ActualizarPrecioDto) {
  return this.productosService.actualizarPrecio(id, dto); // 200: devolvemos el recurso
}
  1. Guarda (recarga sola).
  2. Prueba PUT /api/v1/productos/1 con { "nombre": "Teclado mecánico RGB", "precio": 55.00 }: debe responder 204.
  3. Prueba PATCH /api/v1/productos/1 con { "precio": 60.00 }: debe responder 200 con el producto actualizado.
  4. Prueba ambos verbos con id=999: deben responder 404 (gracias al NotFoundException, que Nest traduce automáticamente al código HTTP correcto).

Pregúntate

¿Por qué PUT exige el objeto completo mientras PATCH solo pide el precio? Relaciónalo con la idempotencia de cada verbo (sección 2.3 de la teoría).

Verificación del Paso 5
  • PUT válido responde 204 y PATCH válido responde 200.
  • Ambos responden 404 con un id inexistente.
Marca ambas casillas para continuar.
Paso 6

Implementar DELETE (idempotente)

  1. Agrega este método a ProductosService:
productos.service.ts
eliminar(id: number): void {
  const index = this.productos.findIndex((p) => p.id === id);
  if (index === -1) throw new NotFoundException(`Producto ${id} no existe`);
  this.productos.splice(index, 1);
}
  1. Agrega este método al controlador:
productos.controller.ts
@Delete(':id')
@HttpCode(HttpStatus.NO_CONTENT)
eliminar(@Param('id', ParseIntPipe) id: number) {
  this.productosService.eliminar(id); // 204
}
  1. Guarda (recarga sola).
  2. Ejecuta DELETE /api/v1/productos/2: debe responder 204.
  3. Ejecuta el mismo DELETE una segunda vez: debe responder 404 — nunca un error 500.
Verificación del Paso 6

Paso 8 · Reto

Enlaces HATEOAS mínimos

Resuelve antes de terminar la sesión

Modifica el método obtener del controlador para que la respuesta incluya _links con self, actualizar y eliminar.

productos.controller.ts
@Get(':id')
obtener(@Param('id', ParseIntPipe) id: number) {
  const producto = this.productosService.findOne(id);
  return {
    ...producto,
    _links: {
      self: { href: `/api/v1/productos/${producto.id}` },
      actualizar: { href: `/api/v1/productos/${producto.id}`, method: 'PUT' },
      eliminar: { href: `/api/v1/productos/${producto.id}`, method: 'DELETE' },
    },
  };
}

Guarda (recarga sola) y prueba GET /api/v1/productos/1: confirma que la respuesta incluye _links con las 3 acciones.
