Paso 3.1

El CLI de NestJS genera la estructura del proyecto y de cada recurso (controlador, servicio, módulo) a partir de convenciones, en vez de que escribas todo desde cero.

terminal

Si ves "command not found" después de instalar, revisa que la carpeta global de npm esté en tu PATH (cierra y vuelve a abrir la terminal antes de darte por vencido).

Paso 3.3

Habilitar Swagger / OpenAPI

terminal
$ npm install @nestjs/swagger

Reemplaza el contenido de src/main.ts:

src/main.ts
import { NestFactory } from '@nestjs/core';
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix('api/v1');

  const config = new DocumentBuilder()
    .setTitle('API Productos')
    .setDescription('API de catálogo de productos — Semana 1')
    .setVersion('1.0')
    .build();
  const document = SwaggerModule.createDocument(app, config);
  SwaggerModule.setup('api/docs', app, document);

  await app.listen(3000);
}
bootstrap();

Guarda y observa la consola (se recompila sola). Abre http://localhost:3000/api/docs.

Nota: como acabas de aplicar setGlobalPrefix('api/v1'), http://localhost:3000/ ya no responde "Hello World!" directamente — esa ruta ahora vive en http://localhost:3000/api/v1. Es esperado.

Esto es documentación code-first: nace de decoradores en tu código, igual que Swashbuckle en .NET o Springdoc en Spring Boot. En la semana 7 verás el enfoque schema-first puro.

Paso 3.6

Implementar el primer endpoint funcional

Reemplaza el contenido de src/productos/productos.service.ts:

src/productos/productos.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';

export interface Producto {
  id: number;
  nombre: string;
  precio: number;
}

@Injectable()
export class ProductosService {
  private readonly productos: Producto[] = [
    { id: 1, nombre: 'Teclado mecánico', precio: 45.90 },
    { id: 2, nombre: 'Mouse inalámbrico', precio: 19.50 },
    { id: 3, nombre: 'Monitor 24"', precio: 129.99 },
  ];

  findAll(): Producto[] {
    return this.productos;
  }

  findOne(id: number): Producto {
    const producto = this.productos.find((p) => p.id === id);
    if (!producto) {
      throw new NotFoundException(`Producto con id ${id} no encontrado`);
    }
    return producto;
  }
}

Reemplaza el contenido de src/productos/productos.controller.ts:

src/productos/productos.controller.ts
import { Controller, Get, Param, ParseIntPipe } from '@nestjs/common';
import { ApiTags, ApiOperation, ApiResponse } from '@nestjs/swagger';
import { ProductosService, Producto } from './productos.service';

@ApiTags('productos')
@Controller('productos')
export class ProductosController {
  constructor(private readonly productosService: ProductosService) {}

  @Get()
  @ApiOperation({ summary: 'Listar productos disponibles' })
  @ApiResponse({ status: 200, description: 'Lista de productos.' })
  findAll(): Producto[] {
    return this.productosService.findAll();
  }

  @Get(':id')
  @ApiOperation({ summary: 'Obtener un producto por id' })
  @ApiResponse({ status: 200, description: 'Producto encontrado.' })
  @ApiResponse({ status: 404, description: 'Producto no encontrado.' })
  findOne(@Param('id', ParseIntPipe) id: number): Producto {
    return this.productosService.findOne(id);
  }
}

Nota el prefijo api/v1 (configurado globalmente en el Paso 3): tu primer contacto real con versionamiento de contratos (evolución controlada, sección 1.1). Nota también el ParseIntPipe: valida que :id sea un número antes de que tu código lo use — si alguien pide GET /api/v1/productos/abc, NestJS responde 400 Bad Request automáticamente.
