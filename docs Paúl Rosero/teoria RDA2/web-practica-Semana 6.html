Horas de práctica de laboratorio

Construye una Saga coreografiada real, con compensación

Vas a construir 4 microservicios NestJS independientes que se comunican exclusivamente por eventos a través de RabbitMQ (@nestjs/microservices, Transport.RMQ): Pedido → Inventario → Pago → Notificaciones, con un correlation-id propagado en cada evento y una compensación real cuando el pago falla.

2.5 h laboratorio NestJS · @nestjs/microservices · RabbitMQ Nivel: Saga coreografiada + reto orquestado
Regla de esta guía: sigue los pasos en orden, sin saltarte ninguno. El botón "Marcar paso completado" solo se activa cuando confirmas la Verificación del paso. El Paso 6 (compensación) es el corazón de esta semana — no lo apures.
Nota: esta semana no tiene una versión previa en C#/.NET — nace directamente en NestJS. El proyecto original de facturación en .NET Framework + SQL Server de contenido/clase 6/practica semana 6.docx (arquitectura por capas, EF6, Saga sobre 3 microservicios de facturación) queda como pista extendida/opcional para quien quiera profundizar en un caso mucho más grande.

nestjs-pedido-service: crear el pedido y publicar PedidoCreado

Reemplaza src/app.module.ts:

import { Module } from '@nestjs/common';
import { ClientsModule, Transport } from '@nestjs/microservices';
import { AppController } from './app.controller';

@Module({
  imports: [
    ClientsModule.register([
      {
        name: 'INVENTARIO_SERVICE',
        transport: Transport.RMQ,
        options: {
          urls: ['amqp://localhost:5672'],
          queue: 'inventario_queue',
          queueOptions: { durable: false },
        },
      },
    ]),
  ],
  controllers: [AppController],
})
export class AppModule {}

Reemplaza src/app.controller.ts:

import { Controller, Post, Body, Inject } from '@nestjs/common';
import { ClientProxy } from '@nestjs/microservices';
import { randomUUID } from 'crypto';

const PEDIDOS: Record<string, any> = {};

@Controller('pedidos')
export class AppController {
  constructor(@Inject('INVENTARIO_SERVICE') private readonly inventarioClient: ClientProxy) {}

  @Post()
  crearPedido(@Body() body: { productoId: number; cantidad: number }) {
    const correlationId = 'cid-' + randomUUID().slice(0, 8);
    const pedido = { pedidoId: correlationId, ...body, estado: 'Creado' };
    PEDIDOS[correlationId] = pedido;

    console.log(JSON.stringify({
      timestamp: new Date().toISOString(),
      service: 'PedidoService',
      event_emitted: 'PedidoCreado',
      correlation_id: correlationId,
      status: 'ok',
    }));

    this.inventarioClient.emit('pedido_creado', { correlationId, ...body });
    return pedido;
  }
}

Piensa

crearPedido no espera ninguna respuesta de Inventario: publica el evento y responde de inmediato — es el desacoplamiento temporal de la teoría §6.4.

Reemplaza src/app.controller.ts:

import { Controller, Inject } from '@nestjs/common';
import { ClientProxy, EventPattern, Payload } from '@nestjs/microservices';

const STOCK: Record<number, number> = { 1: 10, 2: 15, 3: 5 };
const RESERVAS: Record<string, { productoId: number; cantidad: number }> = {};

@Controller()
export class AppController {
  constructor(@Inject('PAGO_SERVICE') private readonly pagoClient: ClientProxy) {}

  @EventPattern('pedido_creado')
  reservarStock(@Payload() data: { correlationId: string; productoId: number; cantidad: number }) {
    const inicio = Date.now();
    const disponible = (STOCK[data.productoId] ?? 0) >= data.cantidad;

    if (disponible) {
      STOCK[data.productoId] -= data.cantidad;
      RESERVAS[data.correlationId] = { productoId: data.productoId, cantidad: data.cantidad };
      console.log(JSON.stringify({
        timestamp: new Date().toISOString(), service: 'InventarioService',
        event_received: 'PedidoCreado', event_emitted: 'InventarioReservado',
        correlation_id: data.correlationId, status: 'processed', duration_ms: Date.now() - inicio,
      }));
      this.pagoClient.emit('inventario_reservado', data);
    } else {
      console.log(JSON.stringify({
        timestamp: new Date().toISOString(), service: 'InventarioService',
        event_received: 'PedidoCreado', event_emitted: 'InventarioRechazado',
        correlation_id: data.correlationId, status: 'rejected', duration_ms: Date.now() - inicio,
      }));
    }
  }

  @EventPattern('pago_fallido')
  revertirReserva(@Payload() data: { correlationId: string }) {
    const reserva = RESERVAS[data.correlationId];
    if (reserva) {
      STOCK[reserva.productoId] += reserva.cantidad;
      delete RESERVAS[data.correlationId];
    }
    console.log(JSON.stringify({
      timestamp: new Date().toISOString(), service: 'InventarioService',
      event_received: 'PagoFallido', event_emitted: 'InventarioLiberado (compensación)',
      correlation_id: data.correlationId, status: 'compensated',
    }));
  }
}

Edita src/main.ts para arrancarlo como microservicio puro (sin servidor HTTP):

import { Transport } from '@nestjs/microservices';
import { AppModule } from './app.module';

}

Paso 6 — El corazón de la semana

La compensación: simular un fallo de pago

Modifica src/app.controller.ts de nestjs-pago-service para que el pago falle una parte de las veces:

@EventPattern('inventario_reservado')
procesarPago(@Payload() data: { correlationId: string; productoId: number; cantidad: number }) {
  const inicio = Date.now();
  const pagoExitoso = Math.random() > 0.4; // ~60% de éxito

  if (pagoExitoso) {
    console.log(JSON.stringify({
      timestamp: new Date().toISOString(), service: 'PagoService',
      event_received: 'InventarioReservado', event_emitted: 'PagoProcesado',
      correlation_id: data.correlationId, status: 'processed', duration_ms: Date.now() - inicio,
    }));
    this.notiClient.emit('pago_procesado', data);
  } else {
    console.log(JSON.stringify({
      timestamp: new Date().toISOString(), service: 'PagoService',
      event_received: 'InventarioReservado', event_emitted: 'PagoFallido',
      correlation_id: data.correlationId, status: 'error',
      error: 'timeout de la pasarela de pago (simulado)', duration_ms: Date.now() - inicio,
    }));
    this.inventarioClient.emit('pago_fallido', data);
  }
}

Reinicia nestjs-pago-service y ejecuta el mismo curl del Paso 5 varias veces seguidas (al menos 8-10 veces) para observar ambos caminos.

Si en 10 intentos nunca ves el fallo

Sube la probabilidad temporalmente: Math.random() > 0.2, y repite.

Paso 8 — Reto

Implementar la versión orquestada

Hasta aquí construiste una Saga coreografiada. El reto es construir, en un quinto proyecto (nestjs-orquestador-pedidos), una versión orquestada del mismo flujo:

  1. Expón POST /pedidos-orquestados, que llama en secuencia, usando request-response (client.send() + @MessagePattern() en cada destino), a: reservar inventario → procesar pago → notificar.
  2. Si un paso responde con error, el propio orquestador —no el servicio que falló— decide y dispara la compensación del paso anterior.
  3. Compara por escrito: ¿qué parte del código es más simple en cada versión? ¿Qué pasaría si agregaras un quinto paso ("generar factura") a cada una?
